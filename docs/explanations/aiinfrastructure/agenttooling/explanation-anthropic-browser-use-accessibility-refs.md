# Anthropic Browser Use: Accessibility-Tree-Based Browser Tooling

## Overview

Anthropic launched a **Browser Use tool** (announced 2026-08-20) that gives Claude a *structured* view of web pages instead of relying on pixels. It is part of a broader release that also brings **Computer Use**, the **Skills API**, and the **Files API** to general availability. Developers access it through the Claude API using the toolset ID `browser_toolset_20260801`.

The key architectural difference from Computer Use:

| | Computer Use | Browser Use |
|---|---|---|
| View | Screenshots | Page structure (accessibility tree) |
| Targeting | Mouse coordinates + keyboard | Element references (`ref_3`, `ref_17`) |
| Scope | Entire desktop | Inside the browser |
| Reliability | Guess positions from pixels | Deterministic element refs |

## How It Works

When Claude calls `read_page`, **the developer's executor** (not Anthropic) returns a text representation of the page's accessibility tree, with links, buttons, and text boxes tagged with references. Subsequent operations target a reference directly instead of computing screen coordinates:

```
Claude: read_page            -> executor returns a11y tree with refs
Claude: click ref_3          -> executor resolves ref_3 and clicks
Claude: type ref_7 "..."     -> executor resolves ref_7 and types
```

## Batched Actions in a Single Turn

Anthropic now allows **multiple actions in one model turn**: several `tool_use` blocks arrive together, the executor runs them in order, and results are returned in one shot — avoiding a model round-trip between every click and keystroke.

- **Benefit:** lower latency and token cost as workflows grow from a handful to dozens/hundreds of interactions.
- **Constraint:** the executor must still run actions *sequentially* (each depends on the prior page state), so a failed first action must stop the sequence.
- **Security implication:** approval gating is harder — a routine first click in a batch can lead to a later action that needs user approval, so the executor must check actions as they happen.

## The Developer Hosts the Browser

Critical detail: **Anthropic does not execute browser actions.** Adding the tool to a Messages API request exposes **27 browser operations** by default; Claude picks which to use, but the application must:

1. Translate each requested operation into an action in *its own* browser environment
2. Preserve the session between turns
3. Return enough post-action state for Claude to understand what happened

**Token cost:** Anthropic's pricing documentation states the default Browser Use toolset adds roughly **6,600 input tokens** per request *before* counting screenshots, accessibility trees, and other returned content. Developers can disable unused operations to reduce overhead.

## DIY Alternative

The toolset is limited to the Claude API (not available in Claude Managed Agents). A developer can approximate it with **Puppeteer**: `Accessibility.snapshot()` exposes the same accessibility tree, and navigation/read APIs control Chrome/Firefox — then maintain Anthropic's reference mappings on top.

> Naming collision: the open-source project [browser-use](https://github.com/browser-use/browser-use) (Chromium via Chrome DevTools Protocol, own agent loop) is **unrelated** to Anthropic's tool despite the shared name.

## Security Posture

- Claude can still hit prompt injection in web content or be redirected — Anthropic recommends running the browser in an **isolated container or VM with minimal access**
- Keep **JavaScript and file uploads disabled** unless needed: JS generated by Claude runs with the page's privileges and can reach data or make requests available to that page

## Key Takeaways

1. **Refs over coordinates** — accessibility-tree references make element targeting deterministic, unlike screenshot-based Computer Use
2. **You run the browser** — the toolset is a contract, not a hosted service; 27 ops must be implemented by your executor
3. **6,600-token default overhead** — disable unused operations or approximate with Puppeteer's `Accessibility.snapshot()`
4. **Batching cuts round-trips** — but forces sequential execution and complicates approval gating
5. **Isolate the browser** — container/VM, JS and uploads off by default
