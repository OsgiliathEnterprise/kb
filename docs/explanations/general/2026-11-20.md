### OpenSSL: Buffer overflow in EVP_EncodeBlock() (CVE-2026-121481, CVSS 9.8)
A buffer overflow in OpenSSL's `EVP_EncodeBlock()` base64 encoding path — triggered by NULL input/output buffers, negative lengths, or lengths whose encoded size overflows an `int` — was disclosed with a public fix PR; the advisory is still pending and the OpenSSL SRT asked for the fix to be done publicly. The reporter demonstrated command-line exploitation by passing a very large `-proxy_pass` to `openssl s_client` (confirmed working against GOST via an environment-variable-supplied password); the pattern mirrors CVE-2021-23840. The proposed fix returns `-1` on invalid input (matching wolfSSL's compatibility layer), adds a similar guard to `EVP_DecodeBlock()`, and corrects a faulty length check in `http_client.c`'s `base64encode()`. Track the PR/advisory and patch as soon as a release ships.
Source: [OpenSSL PR #33652](https://github.com/openssl/openssl/pull/33652) · [GHSA-83xj-7xh4-4p7x](https://github.com/advisories/GHSA-83xj-7xh4-4p7x)

## 🟠 P1 - Important

### PostgreSQL 19 released (2026-11-19)
The headline feature is the new `REPACK` command: `REPACK (CONCURRENTLY)` reclaims table bloat and reorganizes rows while reads and writes continue (brief final lock, logical decoding to capture changes), replacing the risky `VACUUM FULL`/third-party `pg_repack`/`pg_squeeze` paths with a built-in online option. Also new: `pg_plan_advice` + `pg_stash_advice` extensions to control/automatically stabilize query plans, automatic scaling of I/O worker processes, quicker foreign-key checks, logical replication enablement without restart (when `wal_level=replica`), replication of sequence values, "read-your-writes" on standbys via the new `WAIT` command, and parallel autovacuum of indexes with a prioritization scoring system. Migration requires pg_dumpall/pg_upgrade/logical replication; Databricks shipped Postgres 19 on Lakebase the same day, and Snowflake's engineering post is a good practical walkthrough of bloat diagnostics (`pg_stat_user_tables` dead-tuple ratios) and REPACK vs pg_repack. 19.1 is anticipated in February — a sensible production-upgrade target.
Sources: [Release notes](https://www.postgresql.org/docs/release/19.0/) · [Snowflake: Postgres 19 REPACK](https://www.snowflake.com/en/blog/engineering/postgres-19-repack-table-bloat/) · [Databricks: Postgres 19 on Lakebase](https://www.databricks.com/blog/postgresql-19-available-lakebase)

### GIMP now has real UI tests
GIMP added a GUI testing platform that starts a real GIMP in a hidden virtual desktop, clicks menus/buttons, and verifies results — running automatically in CI on every merge. The 13 initial tests cover startup, dialogs, File > New/Export, layers, undo/redo, zoom, toolbox, preferences and menu actions; crucially, tests locate widgets via accessibility information (the same data screen readers use), so improving testability also improves accessibility, and the team contributed a headless-mode feature upstream to dogtail (Linux/X11+Wayland only for now).
Source: [GIMP news](https://www.gimp.org/news/2026-11-16/gimp-ui-tests/)

### I Measured My MCP Server's Context Tax Before Adding a Third Tool
A grounded, measured take on the "MCP context tax": every registered tool's full JSON schema is sent with every request whether used or not, so it's a standing charge per turn. The author's 30-line audit script found his two-tool server costs ~200 tokens/turn (~0.1% of a 200k window) — near-zero, but he notes prompt caching reduces dollar cost, not attention cost, so schema bloat still competes with real work. Useful methodology for anyone about to stack several MCP servers.
Source: [DEV.to](https://dev.to/eliashivemind/i-measured-my-mcp-servers-context-tax-before-adding-a-third-tool-40gg)

### Fiona the Hippo Died After Eating a Hat. But How Does a Hat Kill a Hippo?
Cincinnati Zoo's famous hippo Fiona (9) died from complications after ingesting a knit hat that flew through a one-foot gap above the viewing window after hitting a ceiling fan. A vet explains the mechanics: a hippo's intestine is likely 100+ feet long, so a stuck hat can cause swelling that cuts off blood flow → tissue death → leakage of gut contents → toxic shock; surgery on a hippo's abdomen is rarely viable, and if the hat hadn't passed within ~5 days, outcomes were grim.
Source: [WIRED](https://www.wired.com/story/fiona-the-hippo-died-after-eating-a-hat-but-how-does-a-hat-kill-a-hippo/)
