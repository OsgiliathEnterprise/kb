## 🔴 P0 - Critical

### Java4Shell: critical OpenJDK RCE (CVE-2026-114938, CVSS v4.0 9.2)
A memory-corruption bug in the x86-64 intrinsic implementation of OpenJDK's Base64 decoder allows a heap out-of-bounds write (miscalculated store mask on padded input with a stray `=`), enabling Heartbleed-style heap disclosure and remote code execution. Any application decoding externally supplied Base64 is potentially affected; reportedly exploitable without authentication in some products. Affects OpenJDK/Java SE 17.x, 21.x, 25.x, 27.x on CPUs with AVX-512 VBMI (ARM64 unaffected); fixed in 17.0.21.1, 21.0.13.1, 25.0.5.1, 27.0.1.1, with mitigations `-XX:-UseBASE64Intrinsics` or `-XX:UseAVX=2`. Patch internet-facing JVMs urgently.
Source: [JFrog Security Research](https://research.jfrog.com/post/java4shell-vulnerability/) (via [This Week in Spring](https://spring.io/blog/2026-11-18/this-week-in-spring-november-18th-2026))

### Microsoft's ONNX Runtime has disappeared from GitHub
The main `microsoft/onnxruntime` repo (22k stars) and at least seven related repos return 404 with no advance warning or official explanation — verified personally; source builds and CI pipelines that clone from GitHub are breaking, while pip/NuGet/Maven packages still install. Community theories range from a security disclosure (a March 2026 parser flaw allowing arbitrary file/memory reads via crafted ONNX models was cited in discussion) to a GitHub outage; mirrors (intel fork, SourceForge, syntax-syndicate fork) are circulating but their trustworthiness is unverified — pin cached artifacts and avoid random forks until Microsoft speaks.
Source: [GitHub](https://github.com/microsoft/onnxruntime) · [RuntimeWire report](https://runtimewire.com/article/microsoft-s-onnx-runtime-has-disappeared-from-github-along-with-at-least-seven)

### DuckDB 2.0 "Cinnamon Teal": client-server mode and Agent Mode
DuckDB's biggest release ever (first major since 1.0.0 two years ago) ships the Quack remote protocol as a first-class citizen for networked operation, enables the extensible SQL parser by default, and adds a dedicated Agent Mode with machine-readable JSON errors, no hidden truncation, and runaway-query guardrails for coding agents (Claude Code, Codex, Cursor). The storage format is deliberately broken for compatibility — DuckLabs' own head of DevRel urges not running a .0 release in production and to wait for the imminent 2.0.1.
Source: [The New Stack](https://thenewstack.io/duckdb-storage-compatibility-agents/)

### Harvard: AI coding agents shifted the bottleneck to code review
A working paper (Chen & Stratton, Harvard; Jellyfish + Revelio data across 718 firms, ~726k workers) finds engineers at AI-agent adopters added ~30% more code, yet finished work did not measurably rise and code review took 49% longer. Caveats: job-market paper, not peer-reviewed. Practical takeaway for teams adopting coding agents: measure approved work product, revision rates, and reviewer time — not drafting output.
Source: [ComplexDiscovery](https://complexdiscovery.com/harvard-researchers-find-ai-coding-agents-shifted-the-bottleneck-to-code-review/)

### Google's AI Overviews cut outbound clicks by ~40%
A randomized experiment (Agarwal & Sen, Jan–Feb 2026) hiding AI Overviews from some US desktop users shows Overviews remove ~40% of clicks to outside websites. AI Overviews now appear on 61.4% of tracked US keywords (up from 5.9% in Sept 2024); GEO offers little compensation — AI assistants sent sites just ~0.3% of traffic. Material for anyone with SEO-dependent content strategy.
Source: [RevScope](https://revscope.co/blog/search-seo-geo-2026/)
