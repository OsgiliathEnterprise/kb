📄️LM Studio Bionic Shell Judge and Auto Review — Structural Safety for AI-Generated Commands

LM Studio's coding agent Bionic runs shell commands generated by an LLM. A command as ordinary as git diff becomes dangerous once a variable is involved: git diff $base behaves normally when $base holds a commit hash, but if it resolves to --output=/some/file, Git writes the result to the filesystem. String-matching for "dangerous" tokens cannot catch this — the behavior depends on variables, redirects, and nested commands. LM Studio's answer is Auto Review, a first-layer safety gate that clears as many as 82% of Bionic's commands without another model call (the author calls the figure anecdotal, not a benchmark), escalating to a second language-model judge only when it cannot decide.

📄️The Miasma Worm: How AI Coding Agents Became a Supply Chain Attack Surface

Microsoft disabled 73 GitHub repositories — including the Azure Functions Action — after a supply chain attack that did not target developers at all. It targeted their AI coding agents. The "Miasma worm" is a new threat class: malicious code propagates through agentic CI/CD workflows, using each compromised agent as a vector into the next repository it has write access to.

📄️Office Party: LD_PRELOAD Skill-Composition RCE in Claude Document Skills

Office Party is a flaw in Anthropic's official DOCX, PPTX, and XLSX document skills, found by AIR Security (reported May 2026). A fixed temporary-file path makes LibreOffice load and execute an attacker-supplied shared library on Linux — the code runs with the privileges of the user operating the AI agent. Anthropic acknowledged it but treats it as outside its security boundary because the code runs inside a sandbox; the helper script remains unchanged.

📄️OpenAI Dots — Always-On Agents and the Boundary Problem That Doubles With Task Length

OpenAI's Dots (launched at DevDay 2026) are always-on personal agents when OpenAI doubled chained tasks from 5 to 10, the share of samples flagged for boundary problems rose from 8.6% to 19.7% — roughly doubling with task count. No high-severity breaches or data exfiltration were found in the evaluation, but OpenAI has not disclosed what the flagged boundary problems actually involved.

📄️RFC 8693 Token Exchange: Letting AI Agents Act For Users Without Borrowing Their Identity

When an AI agent calls a downstream API (Microsoft Graph, an internal orders API), an awkward question surfaces: whose access is it? If the answer is "the user's", the agent can do everything the user can do. If the answer is "the agent's own service account", the audit log stops saying who asked for what. Both are the borrowed-identity failure mode (the anticipated companion note "Five Identity Patterns Production AI Agents Need" does not exist in the vault yet).
