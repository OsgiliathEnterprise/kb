## 🔴 P0 - Critical

### NFS2ROOT (CVE-2026-99362): 12-year-old pre-auth remote root in the Linux NFS server
A CVSS 9.8 heap overflow in in-kernel `nfsd`: one unauthenticated TCP connection to port 2049 writes 61 bytes past a kernel heap object (40 attacker-chosen), chained into a root shell. Every kernel since 3.16 (2014) serving NFSv4.1/4.2 is affected — file servers, NAS appliances, build farms, Kubernetes storage nodes. **Fixed in 6.12.117 / 6.18.61 / 7.3.2 / 7.4-rc1: patch, reboot, and firewall tcp/2049 until then.** KB note written.
Source: [OpenSec](https://opensec.in/blog/nfs2root-cve-2026-99362)

### Researcher calls out Ubuntu's slow patching of remote kernel RCEs
Hanno Böck (oss-security): NoisyTCP remote memory corruption (CVE-2026-99288, disclosed Nov 16) still unpatched on Ubuntu nine days later while other distros shipped fixes at disclosure time; AMD KVM host escape CVE-2026-99312 likewise unfixed, and an earlier TCP corruption (CVE-2026-98432) took weeks with active exploitation reported. He argues Ubuntu's strategy of backporting to an old kernel (7.0.0-44) instead of tracking recent kernel.org longterm releases (Debian stable: 6.12.118) is "hardly viable." Directly relevant while NFS2ROOT is unpatched in the wild.
Source: [oss-security](https://www.openwall.com/lists/oss-security/2026/11/25/9)

### minipg: PostgreSQL as a single executable, no server to configure
A `.pgdb` directory *is* the database (data, config, credentials, Postgres version); `minipg app.pgdb` opens psql, auto-starting/stopping the server. It embeds Docker Hub's `postgres:18-alpine` and runs the real Postgres binaries directly on the host hypervisor via h9 with a Plan 9 kernel answering syscalls — no Linux boot, no VM image, no Docker. Static binary works in CI without /dev/kvm. Early: ~2x slower than native on the native backend; don't trust precious data yet.
Source: [minipg](https://progrium.github.io/minipg/)

### Sandbox granularity is your isolation story, not the sandbox tech
Practitioner framework for agent code execution: **per-run** (strongest isolation, no state; fix slow setup with snapshots), **per-session** (state across turns, but a prompt injection in turn 3 can run in turn 7; watch idle billing), **per-user** (persists everything incl. planted artifacts and stale secrets; needs laptop-style hygiene). The one hard rule: never share a sandbox across users, and derive the user→sandbox mapping from authenticated identity, never client input.
Source: [DEV.to (sandscale)](https://dev.to/sandscale/one-sandbox-per-run-per-session-or-per-user-isolation-cost-and-state-trade-offs-1i8f)
