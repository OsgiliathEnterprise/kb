# Where the Tokens Go: Heat, Entropy and Error in Agentic Coding

## Overview
Aspuru-Guzik & Bernales propose a **theory of software thermodynamics** for coding agents: tokens are the currency, and they split into **work** (tokens that move the code toward the requested change) and **heat** (tokens burned by calls that leave the change exactly where it was). The test suite plays the role of a **software Maxwell's daemon**, judging every coding change — and, like a real daemon, it is imperfect and that imperfection has a token cost.

## Problem Statement
Coding agents are billed per token, but software engineering has no account of *what a token buys*. Cost optimization today is guesswork because there is no decomposition of spend into productive vs. dissipated effort, and no measured notion of "how much energy (tokens) a code change intrinsically requires."

## The Theory and the Experiment
- **Work vs. heat**: divide an agent run's token cost into tokens that advance the change vs. tokens from model calls that leave it unchanged.
- **Maxwell's daemon = test suite**: every change is judged by the suite; the daemon's verdicts gate progress.
- **Single-molecule pulling analogue**: an agent repeatedly **codes** a change to a repository and then **uncodes** it (each direction started from a stored reference tree), counting tokens on every model call.
- **Software temperature**: the spread of cycle cost over repeated codings/uncodings defines a temperature — and it **rose with the model's sampling temperature**.
- **Jarzynski-style free energy**: the free energy of a change is estimated by analogy with the Jarzynski equality from the non-equilibrium cycle data.

## Measured Results
- **≈80% of tokens in a successful run are heat** — generated by model calls that leave the requested change where it was.
- **Free energy of a change ≈ 14–22%** of the mean token cost of a successful coding run (the irreducible productive core).
- **Coding costs 1.1–1.5× as much as uncoding** — undoing is systematically cheaper than doing.
- **The daemon leaks**: test-suite verdicts vary with environment, and a suite that accepts a broken change imposes a measurable token cost.

## Why It Matters
- Gives teams a **measurable vocabulary for agent waste**: if ~80% of spend is heat, cost dashboards should separate heat from work instead of counting total tokens.
- Frames agent optimization as reducing dissipation (fewer no-op calls, tighter loops), not just picking cheaper models.
- The environment-dependent daemon reframes flaky test suites as a **direct billing risk**: verdict noise converts into tokens.
- Speculative-but-rigorous bridge between stochastic thermodynamics and SE — expect follow-ups (error/entropy extensions per the title).
