## 🔴 P0 - Critical

### GL.iNet routers and KVMs actively compromised via cloud management vulnerability
On November 20 GL.iNet disclosed that an unauthorized party exploited a vulnerability in its cloud remote-management services to access and install malicious software on some GL.iNet routers and KVM devices. The cloud-side attack path is now fixed and closed, but already-infected devices keep the malware until you flash the model-specific security firmware (e.g. 4.11.1 for MT3000/MT6000/MG1300, 1.10.3 for RM1-family KVMs), which removes it without a factory reset. Check for the IOC process `crond -i /tmp/.log` (LuCI Status → Processes, or `ps | grep tmp` over SSH); if present, treat the device as infected and — for KVMs — also scan the connected computer. If you run any GL.iNet gear, patch today.
Source: [GL.iNet Security Notice](https://www.gl-inet.com/en-us/blogs/blog/glinet-security-notice-2026-11-20)

## 🟠 P1 - Important

### Lessons from operating OAuth for 1,000+ APIs (Nango)
Nango recounts a May 2025 bug that silently discarded refreshed credentials for two hours: harmless for most APIs, but for providers with refresh-token rotation (Airtable, Atlassian; optionally Salesforce/Slack) the old tokens were irreversibly burned and every affected user had to re-consent. Key takeaways: treat refresh tokens like money, not cache (persist the new token before anything else can fail), and remember OAuth providers are not interchangeable — Airtable revokes the entire authorization on a stale/duplicate refresh after its grace period and invalidates the old access token instantly. A strong operational reference for anyone building integrations or agent tooling on top of OAuth.
Source: [Nango blog](https://nango.dev/blog/lessons-from-operating-api-auth-for-900-apis/)

### A treemap of the Lean formalization of the Riemann Hypothesis
Pengowray published an interactive treemap of the full Lean proof of the Riemann Hypothesis (following Alpöge's result and jae-63's blueprint): the claim itself lives in just two files (`Statements.lean` + `Main.lean`) that cite 175,185 Mathlib modules, and a single rebuild clocked ~1,067 hours across 175,187 modules. Each rectangle is a module sized by build time/lemma count, hovering over symbols shows their Lean statements — a rare x-ray of what machine-checked mathematics at this scale actually costs and looks like.
Source: [Lean RH proof treemap](https://pengowray.github.io/riemann-zeta-proof-visualizer/)

### XNU Linux: macOS userspace running inside Linux as a kernel module
A new project (256+ commits, actively developed) runs Apple's XNU kernel as a loadable module *inside* Linux on arm64, providing a full macOS GUI userspace personality on top of Linux — Objective-C++/C/C++/Rust mix, with CI building the `xnu.ko`/`fki.ko` modules on arm64 Ubuntu. An audacious OS-hybridization hack in the spirit of WSL-but-inverted; early-stage, but fascinating for kernel folks and cross-platform tooling.
Source: [AFK-surf/xnulinux on GitHub](https://github.com/AFK-surf/xnulinux)

### Tim O'Reilly: "What Happened to Silicon Valley?" — from value creation to value extraction
Tim O'Reilly's Margaret Levi lecture (Johns Hopkins, Oct 16) argues Silicon Valley's turn to surveillance-capitalist extraction isn't about bad people but about the incentive machine set by Friedman-era shareholder capitalism: companies earn virtuous "rising tide rents" while innovating, then slide into "robber baron rents" (a.k.a. enshittification) once growth slows, using market power to hold profits they no longer earn. His prescription is to "reprogram" the corporate machine so human flourishing, not shareholder value, is its objective function. One of the sharper structural critiques of Big Tech/AI economics this quarter.
Source: [O'Reilly Radar](https://www.oreilly.com/radar/what-happened-to-silicon-valley/)
