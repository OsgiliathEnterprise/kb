Self-Hosting Vector Map Tiles with Protomaps PMTiles and Bunny.net

Commercial map APIs get prohibitively expensive when a project goes viral (Mapbox charges $5 per 1k map loads past the free tier). PMTiles (part of the Protomaps ecosystem) replaces the whole tile-serving backend with a single file addressed via HTTP Range requests — any CDN that caches Range requests of large files can serve it, with no server at all.

Why this works​

A .pmtiles archive packs all vector tiles (x/y/z) into one file with an internal directory index. The browser asks for byte ranges, not tile URLs. No tile server, no database, no rendering pipeline at request time — just static file serving. (For CDNs that can't do Range caching, like Cloudflare, Protomaps documents an edge function that translates x/y/z paths into Range requests.)

Format internals (current spec: v3)​

  • 127-byte fixed header at offset 0 holds everything needed to decode the archive (tile type, compression, min/max zoom, pointers to the metadata and root directories) — a client needs exactly one small Range request to bootstrap.
  • Internal directory maps tile IDs → byte offsets/lengths; in v3 it is itself chunked and gzip-compressed, with run-length encoding for contiguous tiles. The planet-scale build addresses 350M+ tiles with a ~91.6 MB directory, ~3× better than generic compression.
  • Tile payloads can be stored uncompressed, gzip, brotli, or zstd (brotli/zstd require clients that can decompress them).
  • Reading a tile costs only a small constant number of Range requests — 127-byte header, the gzip-compressed directory chunk, then the tile bytes (the header/directory reads amortize away once cached), so CDN Range caching collapses latency to roughly one RTT per new tile after warm-up.
  • If you need transactional/atomic tile updates, the docs explicitly steer you to a database (SQLite, or PostgreSQL + ST_asMVT) instead of PMTiles — the format is immutable-artifact oriented: version by filename, not in place.

1. Get a tiles file​

  • Whole world: download the latest daily build from the Protomaps build page.
  • Smaller extract: use the go-pmtiles CLI to extract a bounding box or zoom-range only — dramatically smaller files.

2. Upload to edge storage (Bunny.net, S3-compatible)​

Bunny.net supports Range-request caching, drops the last IP octet by default, and is EU-based. Create a storage zone with S3 compatibility enabled — the plain HTTP API upload times out after 15 minutes for large files. Stream the file in with rclone (run inside tmux or from a temporary VPS on flaky connections):

rclone config create bunnycdn s3 \
  provider=Other \
  access_key_id="<zone-name>" \
  secret_access_key="<storage-key>" \
  endpoint="https://<primary-region>-s3.storage.bunnycdn.com"

rclone copyurl "<build-url>" "bunnycdn:<zone-name>/<filename>.pmtiles" \
  --s3-chunk-size 256M \
  --progress

3. Configure the pull zone​

Point a pull zone at the storage zone as origin, then change three settings:

  1. Security → General → Allowed referrers: restrict embedding to your own domains.
  2. Caching → "Optimize for large object delivery": ON — this is what makes Range requests cacheable. Without it you pay origin egress per tile.
  3. Network limits → Download speed limits + Limit after: cap at 10 kB/s after 10 MB transmitted in a single request. Legitimate browsing never gets near 10 MB; this stops someone from curl-ing the whole file and handing you a CDN bill. Optionally add a req/s limit and a monthly bandwidth cap on the pull zone (note real traffic spikes can legitimately reach high req/s).

4. Embed with MapLibre GL​

npm install pmtiles
import maplibregl from "maplibre-gl";
import { Protocol } from "pmtiles";

let protocol = new Protocol();
maplibregl.addProtocol("pmtiles", protocol.tile);
{
  "sources": {
    "protomaps": {
      "type": "vector",
      "url": "pmtiles://https://<cdn-host>/<filename>.pmtiles"
    }
  }
}

The pmtiles:// scheme auto-derives minzoom/maxzoom for the source. Call addProtocol exactly once per app lifecycle — in React, put it in a useEffect on the root component and removeProtocol on cleanup. For raster or terrain tiles change type to "raster" or "raster-dem" (with "encoding": "terrarium"). Full details: Protomaps MapLibre docs.

Cost reality check​

Bandwidth to Europe/North America is ~$0.01/GB ($0.005/GB on the Volume network); storage $0.01–0.055/GB/month by replication level. The 139 GB world map at 5-continent replication runs ~$5/month in storage. Loading a Europe map and zooming into a city moves ~5 MB → $0.00005 per visit, with reloads nearly free thanks to local caching. At $0.05/1k map loads that is roughly 100x cheaper than Mapbox — with the caveat that Mapbox bills a flat fee per visit regardless of heavy users, while you pay per byte.

Gotchas​

  • Replication factor mostly matters for cache-miss latency, not durability of a rebuildable artifact.
  • Personal-data posture: Bunny drops the last IP octet by default, but any personal data you transmit through the CDN is still processed by them.
  • The article's author flags the Bunny link as an affiliate link.
