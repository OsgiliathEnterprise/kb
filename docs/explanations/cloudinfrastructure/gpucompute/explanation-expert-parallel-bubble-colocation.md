# BubbleTea: Harvesting Expert-Parallel Bubbles for Fine-Tuning

## Overview
GPUs stay expensive while latency-critical LLM inference leaves part of them idle. Colocation reclaims that capacity by running best-effort work (e.g., fine-tuning) alongside serving. **BubbleTea** is the first colocation system that targets a *new* idle-time source introduced by Mixture-of-Experts: under expert parallelism, the router sends uneven token counts to each GPU, so lightly loaded GPUs wait for the most loaded one — **8–13% of prefill time** even after load-balancing.

## Problem Statement
Existing colocation systems (e.g., LLMStation) make a single scheduling decision for all GPUs per forward pass, which cannot exploit per-GPU, per-layer idle gaps. MoE expert parallelism creates fine-grained "bubbles" that prior systems leave unused.

## Key Contribution
- **Per-GPU bubble prediction:** BubbleTea predicts each GPU's bubble at every layer directly from the router's token assignment, instead of one global decision per forward pass.
- **Chunk filling with resident weights:** bubbles are filled with short chunks of fine-tuning work that reuse the weights already loaded for serving — no extra memory pressure for a separate training copy.
- **Compiler passes** automatically derive these fine-tuning chunks from the served LLM as-is, avoiding porting each model architecture to a separate training engine.

## Technical Approach
The serving router's token distribution is the scheduling oracle: it determines which GPUs will idle at which layers. The system then slices fine-tuning work into layer-aligned chunks (generated by compiler passes over the served model definition) and dispatches them into predicted bubbles, keeping the latency-critical path prioritized.

## Results
- Evaluated on three MoE models served on four A100 GPUs: fine-tuning throughput **1.9–6.2× faster than LLMStation** (state-of-the-art colocation).
- Inference SLO: p90 latency within 10% of serving-alone in **50 of 63 workloads** (LLMStation: 44).
- On bursty production traces: **3.3× faster than LLMStation** and **14× faster than a stock trainer colocated under CUDA MPS**, with p90 inference latency within 7% of serving alone.

## Relevance to Our Domain
For GPU fleets running MoE serving, this quantifies a previously ignored waste channel (EP bubbles, 8–13% of prefill) and turns it into free fine-tuning capacity without a dedicated training cluster. The "compiler derives training chunks from the served model as-is" trick removes the usual porting cost that blocks colocation adoption.
