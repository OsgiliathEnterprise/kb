# NariQ: Sub-3-Bit Quantization for Long-Horizon Agentic Tasks

## Overview
NariQ is a post-training quantization method that closes the gap between how low-bit quantization is *evaluated* (short web text, perplexity) and how quantized models are actually *used* in agentic serving: thousands of tool calls across 100K+-token contexts. By calibrating on the right data — the BF16 model's own agentic session output — it claims the first sub-3-bit quantizations that match full precision on long-horizon agentic benchmarks.

## Problem
Standard low-bit quantization pipelines calibrate on short web text and judge quality by perplexity. The paper quantifies the cost of that mismatch: published sub-3-bit quantizations of Qwen3.8-27B stay competitive with BF16 on short tasks like AIME, yet solve **at most 72% as many tasks as BF16** on DeepSWE, a long-horizon agentic benchmark. For agent serving, perplexity-style metrics silently hide catastrophic task-level degradation.

## Specification
| Item | Value |
|---|---|
| Method | Trellis-coded post-training quantization |
| Calibration data | Tokens generated by the BF16 model itself during agent sessions (self-generated, in-domain) |
| Target model | Qwen3.8-27B |
| Bit rates validated at parity | 3.0 and 2.5 bits per weight |
| Degraded bit rate | 2.0 bits per weight (trails the parity tier) |
| Benchmarks at parity with BF16 | DeepSWE, Terminal Bench (long-horizon agentic), AIME, RealWorldQA |
| Artifacts | Qwen3.8-27B-NariQ-GGUF (Hugging Face: nari-labs/Qwen3.8-27B-NariQ-GGUF) |
| Inference | llama.cpp fork (github.com/nari-labs/nari-llama.cpp) |

## Key Contribution
- Agentic-session calibration replaces short-web-text calibration: the quantization grid is fitted to the token distribution the model actually produces during long tool-call loops, not to prose.
- First published quantizations at ≤3 bits per weight shown to match their full-precision version on long-horizon agentic tasks.
- Ships runnable artifacts (GGUF checkpoints + inference fork), making the claim reproducible in llama.cpp-style local serving stacks.

## Relevance to Our Domain
Directly relevant to local/self-hosted agent serving (the KB's llm-serving and local-ai-agents coverage): it changes the acceptance-test story for low-bit models. Perplexity on short text is not a sufficient gate for agent workloads — DeepSWE/Terminal Bench-style long-horizon evals are required, and calibration-set choice is as decisive as bit rate. The 2.0 bpw cliff is a practical deployment boundary to remember.
